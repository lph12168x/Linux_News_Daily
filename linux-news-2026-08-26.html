LLVM/Clang 23.1 发布：全面支持 AMD Zen 6 与 NVIDIA Rigel，部分 C++26
计算
LLVM 23.1 今日按期发布，作为 LLVM 23 系列首个稳定版（H2'2026 更新）。亮点包括：新增 AMD Zen 6「znver6」支持、x86 轻量级故障隔离（LFI）目标、NVIDIA Rigel 核心初始支持（用于 NVIDIA Rosa 处理器）、Arm C1-Ultra 调度模型、AMD HIP 卸载驱动、部分 C++26（-std=c++2c）与 C2Y 语言功能、LLD 链接器改进、AMDGPU GFX1310 目标、SpacemiT X100 RISC-V 目标，以及随 znver6 引入的 AVX-512 BMM 指令支持。源码已在 GitHub 放出，预编译二进制将稍后发布。
关注理由：编译器是图形/计算栈的基座。AMD Zen 6 与 NVIDIA Rigel（Rosa CPU）指令级支持让新一代 CPU 在 Linux 上的内核编译与本地优化更早就位；AMDGPU GFX1310 与 HIP 卸载驱动直接服务于 ROCm/AMD 计算生态；AVX-512 BMM 是 AI 矩阵运算的关键加速。对从事 Linux 图形驱动、AI 计算与跨架构编译的开发者，这是必须跟进的工具链节点。

COSMIC Epoch 1.7 发布：文件管理器浏览网络文件系统不再卡顿
显示
System76 主导的 Rust 桌面环境 COSMIC Epoch 1.7 今日发布。最显著的改动是 COSMIC-Files 文件管理器通过 SFTP 等协议浏览网络文件系统大幅提速——此前自 2024 年起就存在的 bug：目录内文件越多加载越慢、且网络流量远超 GNOME Nautilus。根因是远程文件此前被当成本地文件处理，新补丁（PR #1996）增加了远程文件系统检测、避免对非本地文件做多余操作。此外 1.7 还修复了「解锁后始终点亮屏幕」、合成器每次按键逐级放大缩放等问题。
关注理由：COSMIC 是少数从头用 Rust 构建的 Wayland 原生桌面之一，其迭代速度持续反映 Linux 桌面在显示/合成方向的务实进展。网络文件系统浏览卡顿是文件管理器长期痛点，1.7 的修复直接改善远程开发/运维场景的桌面体验；与同期 KDE Plasma 6.8 的远程桌面改进（见第 5 条）共同勾勒出「远程 + Wayland」体验正在补齐的趋势。

Intel Xe3P / Nova Lake 的 DisplayPort 2.1 ALPM 仍在推进（v5 补丁）
显示
Linux 7.3 内核正把 Nova Lake Xe3P 图形标记为稳定、默认启用并移除 force_probe 强制探测，但部分功能仍未落地，其中就包括 DisplayPort 2.1 ALPM（Advanced Link Power Management，高级链路电源管理）。该功能自 2025 年 11 月起就有 Intel 准备 Xe3P 驱动支持的报道，今天发出的是第 5 版补丁。DP 2.1 ALPM 通过对 sink 设备做快速唤醒/快速休眠，在空闲时段提供更优的省电（尤其对 eDP 笔记本屏），并在活动恢复时迅速响应。尽管补丁已存在近一年，仍未合入。
关注理由：在 Nova Lake 即将铺货、Linux 7.3 图形支持大体就绪的背景下，DP 2.1 ALPM 能否合入直接关系到下一代 Intel 笔记本在 Linux 下的续航/功耗表现——空屏或低活动时的链路省电对移动设备至关重要。v5 的补丁活跃意味着功能临近落地，值得持续跟踪；也折射出「图形默认可用」与「细分电源特性完全就位」之间的时间差。

实测：Wayland「本质上比 X11 更快，但不一定更高效」
显示
主打高性能、模块化、极简的 PorteuX Linux 为给 Xfce 的 xfwm4 窗口管理器加入 OpenGL 合成，fork 出 「xfwm4-gl」，并借此开发了一套窗口管理器/合成器基准（wmbench）。在 AMD Ryzen 7 7840HS + Radeon 780M 核显 + 32GB 的 PorteuX 2.8 上对比 Wayland 与 X11 各组合后，他们得出结论：「Wayland 本质上比 X11 更快，但不一定更高效」——在纯合成（排除 openbox）场景中，新的 xfwm4-gl 表现最佳。KDE Plasma on Wayland、Labwc、COSMIC 紧随其后；而能效上 LXDE+Openbox（X11）与 xfwm4-gl 略优于 Wayland 方案，LXDE/Openbox 与 Xfce+xfwm4-gl 的 CPU 占用也最低。
关注理由：这场「Wayland 更快但未必更高效」的实测，给长期争论提供了量化数据：在合成延迟/响应上 Wayland 确有结构性优势（尤其 KDE Plasma Wayland、Labwc、COSMIC），但 X11 轻量组合在功耗与 CPU 占用上仍有一席之地。对选择 Linux 桌面与合成器、以及在笔记本上权衡性能与续航的用户，这是一份有参考价值的第三方基准。

KDE Plasma 6.8 远程桌面体验改进，缩小 X11 与 Wayland 差距
显示
KDE 开发者 David Edmundson 发文介绍为 Plasma 6.8 持续进行的远程桌面改进，目标是补齐 X11 已满足、而 Wayland 尚缺的能力。无人值守模式得到增强：远程屏幕按客户端屏幕布局自动缩放/调整尺寸、会话关闭后用户重新登录宿主机；剪贴板功能「大幅改进」，支持双向文本片段，并为文件传输等做准备；同时降低延迟、提升性能，并拓宽 RDP 兼容性、启用 libei 模拟输入支持等。开发者还计划 Plasma 6.8 之后探索多用户无头支持与更好标准化。
关注理由：远程桌面一直是 Wayland 相对 X11 的短板之一，Plasma 6.8 的这一轮改进（无人值守自动缩放、双向剪贴板、低延迟、RDP 兼容、libei 输入）直接关系到 Linux 在远程办公/运维场景的竞争力。与第 2 条 COSMIC 1.7 的网络文件系统提速共同指向一个趋势：原生 Wayland 桌面正系统性补齐「远程 + 网络」体验短板。

Linux 7.0-mk2 发布：多内核架构（multikernel）首度公开，性能可期
内核
去年提出的 多内核（multikernel）架构今日以 Linux 7.0-mk2 形式首度公开释出——把补丁便捷地打到 Linux 7.0 内核树上便于测试。它允许多个独立内核实例在同一物理机上共存：宿主内核拥有一池 CPU/内存/PCI 设备，把资源切分为实例，并通过 kexec_file_load() 把派生内核引导进每个实例；每个派生内核在专属 CPU、物理内存与设备上原生运行，无需虚拟机监视器。实例用写入 /sys/fs/multikernel/ 的设备树声明，资源可在不重启下迁移/回收/重生。相比虚拟机无 VM exit、无二级页表、无设备模型；相比容器，实例不共享内核，单核锁定/崩溃/漏洞不会越界。官方基准显示其在 2 核对比中优于 KVM，24 核配置下双内核运行也优于单内核。
关注理由：多内核架构为 Linux 上的隔离与性能提供了介于虚拟机与容器之间的新范式——无虚拟化开销、内核级隔离。对高安全/多租户计算、以及需要把不同内核版本/配置并行跑在同一硬件上的场景（如驱动验证、确定性强隔离）有潜在价值。虽何时进主线尚不明朗，但 7.0-mk2 的公开与基准让这一方向从 RFC 走向可实测。
