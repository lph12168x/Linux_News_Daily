Linux 7.3 在 Intel Panther Lake / Framework Laptop 13 Pro 上带来性能提升（Arc B390 Xe3 集成显卡接力增益）
图形 计算
在 Ubuntu 26.04 LTS 上，用 Framework Laptop 13 Pro 旗舰机（Intel Core Ultra X9 388H）对比了 Linux 7.2 与 Linux 7.3 Git 内核（取自 Ubuntu Mainline Kernel PPA）。背景：Linux 7.1 为 Panther Lake 带来性能改进，7.2 增强了集成 Arc B390 Xe3 显卡性能，7.3 则整体又有多处提升。本次实测未发现明显回退（no scary regressions），在若干项目上有性能增益；结合此前 7.3 在其他硬件（如 AMD EPYC）上的基准，即将到来的 7.3 内核对热门 Panther Lake 笔记本也有收益。
关注理由：对做图形/计算栈的团队，这条把「内核版本代际对集成显卡与整体性能的实际影响」落到具体硬件：Arc B390 Xe3 在 7.2→7.3 持续吃增益，说明新硬件的驱动/调度红利要在数个内核版本里逐步释放。我们评估 zeus 主机侧内核版本（尤其是调度器、GPU 电源管理、内存子系统）对加速器整体吞吐的影响时，不能只看首版支持，要跟踪 2~3 个版本的累积收益；同时「无回退但有增益」也提示升级内核时的回归测试重点应放在这些增益路径上。

Valve Steam Frame 现已开售，起价 $1059：骁龙 8 驱动的 VR/游戏一体机，100+ 验证游戏
计算 图形
Valve 期待已久的 Steam Frame 头显现已开售：256GB 版 $1059，1TB 版 $1299（各地区定价同步公布）。套装含无线 VR 头显与控制器，随购附赠《Half-Life: Alyx》，目前已有 100+ 款 Steam Frame Standalone Verified 游戏。设备由高通骁龙 8（Snapdragon 8）SoC 驱动，采用预约（reservation）系统以限制黄牛。
关注理由：对做图形/计算栈的团队，Steam Frame 是「独立 VR/游戏一体机跑 Linux 生态」的又一个重量级落地：骁龙 8 SoC 意味着它走 Arm + 移动 GPU 路线，与我们在「异构加速器 + 统一内存」上的关注点一致。100+ 验证游戏说明 Valve 的 Proton/兼容层在 Arm 移动 GPU 上已能撑起一摊生意，对 zeus 这类自研加速器评估「上层运行时兼容（Vulkan/游戏/多媒体）」有参考价值；其预约限量的发行策略也值得在做硬件产品发布时借鉴。

AMD 为 EPYC 虚拟机准备增强型 SMT 保护「ESMTP」：硬件级隔离缓解侧信道（SEV-SNP，opt-in）
计算
AMD 工程师向 Linux 内核邮件列表提交补丁，开始在 EPYC 服务器处理器（配合 SEV-SNP）上为虚拟机启用 Enhanced SMT Protection（ESMTP）。这是该机制首次出现在内核列表（AMD 白皮书此前已低调发布，推测是 EPYC 9006「Venice」的特性）。与已有的 core scheduling 不同，ESMTP 是硬件级保障：当一个 vCPU 处于 guest 模式时，其所在物理核的 SMT 兄弟线程要么在 host 模式空闲，要么运行该 guest 自己声明的合法兄弟 vCPU，从而缓解 SMT/Hyper-Threading 侧信道风险。需配合 QEMU 与 OVMF 补丁，且仅在启用 SEV-SNP 时可用；因有性能代价（VMRUN 要等兄弟线程就绪），目前为 opt-in 默认不开启。
关注理由：对做计算/虚拟化栈的团队，ESMTP 把「SMT 兄弟线程的信任边界」从内核策略（core scheduling 的 cookie 协调）上移到硬件强制，是侧信道防护的范式升级。它提醒我们：① 在 zeus 做多租户/虚拟化隔离时，「兄弟线程共享核资源」本身就是攻击面，硬件级隔离优于 OS 级策略；② opt-in + 性能代价的设计哲学值得借鉴——安全特性默认不强制，留给租户按威胁模型自选，避免一刀切拖垮普遍负载。

Firefox 156 发布：内置 PDF 阅读器启动最快提速 45%，Vulkan Video 解码仍留 nightly
显示
Mozilla 提前发布了 Firefox 156.0 二进制（正式公告周二）。主打内置 PDF 阅读器启动最快提速 45%；性能侧还改进了显示大幅缩放后适配网页的大尺寸 JPEG 时的内存与 CPU 占用。修复包括部分网站高采样率 FLAC in MP4 失败等问题。值得注意：nightly 中已为较新 NVIDIA GPU + 新版驱动启用 Vulkan Video 解码，但 156 正式版仍将其留在 nightly 门后。
关注理由：对做显示/渲染栈的团队，这条有两点启发：① PDF 阅读器启动 45% 提速与「大 JPEG 缩放后内存/CPU 优化」都指向同一命题——渲染管线的冷启动与内存 footprint 直接决定交互体感，和我们做 zeus 呈现层「首帧延迟/资源占用」的优化目标一致；② Vulkan Video 解码已在 nightly 为 NVIDIA 启用却未进正式版，印证「新图形后端先夜间版灰度、再随驱动成熟转正」的稳妥节奏——我们评估给 zeus 引入新渲染后端/硬件加速路径时，也应先做可选/实验通道，而非默认开启。

GNU Coreutils 9.12 发布：cut -w 吞吐最高 4 倍、uniq -c 快 2.5 倍，新增 uname 标注选项
计算
GNU Coreutils 9.12 发布，包含一系列修复、新选项与性能改进。修复了 chcon/chgrp/chmod/chown/du/ls 用递归 -R 遍历时若文件被并行删除会失败的长期 bug；stat 与 tail 现支持新的 FailFS 与 NULLFS 文件系统类型；uname 新增 -A/--all-labeled 选项，逐行标注并展示全部输出。性能侧：cut -w 吞吐最高提升 4 倍，uniq -c 在使用未锁 stdio 的系统上最高快 2.5 倍，sort 在读取管道等未知大小输入时更好地利用可用内存与并行；cp/install/mv 在 --reflink=auto 因各类错误（如 XFS 元数据空间耗尽）失败时回退到标准拷贝。
关注理由：对做计算/工具链栈的团队，Coreutils 虽属「基础用户态」，其优化却击中我们日常数据流与构建流水线的痛点：① cut -w/uniq -c 的吞吐与并行改进，对日志/数据处理脚本的端到端耗时直接相关；② sort 更好地用满内存与并行、cp/mv 的 reflink 回退，暗示「现代文件/文本工具已默认吃多核与 CoW 文件系统」——我们在 zeus 配套脚本与数据搬运逻辑上应主动利用 reflink/并行，而非仍按单线程思维写。基础件的小版本也可能显著改变大规模流水线的尾部延迟。
