Intel ANV 驱动为 DG2/Alchemist 启用 Vulkan Video AV1 编码
图形 视频
由 Igalia 的 Hyunjun Ko 主导的 Intel ANV Vulkan 驱动，已在 Mesa 26.3-devel 中合并对 DG2/Alchemist 硬件的 Vulkan Video AV1 编码支持（KHR_video_encode_av1）。Gen12.5 硬件现可经 ANV 暴露 AV1 视频编码能力，作者在 DG2 Arc A 系列 显卡上完成测试。这是继去年 ANV 落地 AV1 解码、上月新增 H.265 10-bit 编码之后的又一进展；该补丁已用 FFmpeg 的 Vulkan Video 支持在 Arc A 系列上成功验证。仍需补完的包括 10-bit 编码、multi-tiling 支持，以及 loop filter/restoration 与 CDEF 支持。
关注理由：AV1 编码是视频创作、串流与录屏场景的关键能力。Intel 核显/独显在 Linux 上的 Vulkan Video 栈持续补齐——从解码到 H.265 再到 AV1 编码，意味着开发者可在统一 Vulkan 路径下完成硬件加速的视频管线，减少对 VA-API 单一后端的依赖。对需要在 Linux 上做视频生产、游戏录制或低延迟串流（如 Steam/游戏相关）的用户，是可及性上的实质提升。

Linux 为 2018~2019 款 MacBook Pro 补上混合显卡（GMUX）支持
图形 显示 内核
Andre Eikmeyer 今日向 Linux 内核邮件列表提交补丁，为 2018~2019 款 Apple MacBook Pro 带来 Apple GMUX 混合显卡支持。此前以核显启动时，独立 GPU（dGPU）无法在 GMUX 将其断电后重新唤醒，导致无法在需要时切到独显运行更重的图形/游戏负载。该系列补齐了 apple-gmux、amdgpu 与 HDA 控制器 之间的电源生命周期：以核显为主显示时，dGPU 在 DynOff 与 DynPwr 间切换、经 DRI_PRIME 卸载到独显、外接显示器均可用。MacBookPro15,1 在独显常驻时整机空闲功耗约 24W（其中约 12W 来自闲置独显），补丁后该浪费被消除。已在 2018/2019 两代机型上测试三周（运行/系统挂起恢复、重复唤醒、Thunderbolt/USB-C 外接显示器）。
关注理由：这是一块「近十年老硬件」在 Linux 上可用性/续航的明显改善：同一台 MacBook Pro，补丁前后空闲功耗差约 12W，且终于能用上独显跑游戏/外接显示器。混合显卡（可切换显卡）是笔记本图形体验的核心命题，该补丁把苹果 GMUX 机制纳入主线考量，对想在 Linux 下复用老 Mac 做轻量游戏/外接显示的玩家有直接价值。

Linux 7.2 因「fair」调度策略引发回归，回退到 FIFO DRM 调度
图形 内核
Linux 7.2 的 DRM（Direct Rendering Manager）改动之一是把手内核图形驱动共用的 DRM 调度器默认策略从 FIFO 改为 fair（由 Igalia 的 Tvrtko Ursulin 主导，意在更公平），被 AMDGPU 等多家 DRM 内核图形驱动使用。但因上周末一份回归报告，Ursulin 决定在 7.2 中回退。报告人 Luke Wildhardt 指出：fair 策略在 AMD Radeon RX 9070 XT 持续 100% GPU 负载下导致「严重」性能退化——经 Proton 运行的游戏降到约 10 FPS 或彻底卡死、KDE Plasma Wayland 会话整体冻结，需重启或杀掉合成器才能恢复；降低 GPU 负载即停止卡顿。距 7.2 稳定版（预计本周日）不到一周，Ursulin 选择稳妥回退以待彻底排查。相关的 20 个回退补丁 本周作为 DRM fixes 合入主线。
关注理由：一个面向「公平性」的调度器改动，在 RX 9070 XT 满载下却引发桌面整体冻结——这提醒我们内核图形栈的默认策略对实际用户体验影响巨大，也展示了开源回归反馈机制的快速纠偏。对用 AMD 新卡、又跑 Proton 游戏或 Wayland 桌面的用户，7.2 回退到 FIFO 意味着避免一次潜在的严重卡顿；也值得关注 fair 策略后续如何修复后再进主线。

Intel LLM-Scaler 支持 Muse Glimmer 等模型，扩充 Arc B 系列 AI 栈
计算 GPU
Intel 的 LLM-Scaler 项目源自 Project Battlematrix 计划，旨在让 Arc（Pro）B 系列 显卡更易跑生成式 AI——以 Docker 预配置 AI 栈集成 vLLM、ComfyUI、SGLang 等流行软件。本周发布带来多项更新：LLM-Scaler-vLLM beta 0.21.0-b3 为 Meta 新发布的 Muse Glimmer 30B 提供同日支持（FP8 在线量化，可在 Arc Pro B70 上运行），并新增 DFlash 支持（Muse-Glimmer-30B、Qwen3.6-27B），改善 Gemma-4-31B/26B 的首 token 延迟。同日发布的 LLM-Scaler-Omni beta 0.2.0-b1 升级到 ComfyUI 0.31 XPU 栈，新增 MiniMax H3 本地视频生成、Wan Animate 2（Arc Pro B70/B60）、Wan 2.2 14B T2V Turbo、LTX-2、Z-Image/Lumina、Krea2 等，并加入受管 GGUF Q4_1 支持。
关注理由：这是 Intel 在「让 Arc 显卡成为好用的本地 AI 平台」上持续加注的又一信号：以预配置 Docker 栈封装 vLLM/ComfyUI/SGLang，并对新模型（Muse Glimmer 30B、Qwen3.6、Gemma-4、各类视频生成模型）做到快速/同日支持。对想在 Linux + Intel Arc（尤其 B 系列 32GB 显存机型）上跑大模型/多模态/AIGC 的用户，降低了环境搭建门槛，是计算方向的重要进展。

Comma.ai 推出开源固件 eGPU 坞，含 AMD Radeon RX 9060 8GB
图形 显示
George Hotz 与其 Comma.ai / Tinygrad 团队今日发布 Tiny Chestnut eGPU Dock 与 Chestnut Dock，后者内置 AMD Radeon RX 9060 8GB 显卡。亮点在于它运行 开源固件：固件已在 GitHub 公开，是针对 ASM2464PD（USB4/Thunderbolt 转 NVMe 桥接控制器）的 C 语言固件。该坞通过 PCIe Gen4 x4 转 USB4 连接，本质上是一个「放大版 eGPU 坞」——Comma.ai 主用途是给其辅助驾驶系统扩容（从 10W 算力上限扩到 100W、跑更大模型），但也明确可接到普通 PC 当 USB4 扩展坞使用，并兼容 Tinygrad。Tiny Chestnut 单独售价 $249，含 RX 9060 的 Chestnut 套装 $799。
关注理由：把 eGPU 坞的桥接固件开源，在 Linux 兼容性与可审计性上比多数闭源雷电/USB4 坞更友好；内置 RX 9060 也提供了一块开箱即用的中端 Linux 显卡选项。对想给笔记本/迷你机加一块 AMD 显卡做图形或计算、又看重开源固件的玩家，这是个有意思的硬件信号（也呼应了「Linux 上 AMD 显卡驱动体验持续改善」的大趋势）。

LACT 0.10 发布：新增 NVIDIA 超频控制与 Blackwell 热点传感器
图形
LACT 是跨 NVIDIA / AMD / Intel 显卡的流行第三方 Linux GPU 配置与监控工具（GUI），在 AMD Radeon 与 Intel Arc 缺乏官方图形控制面板的 Linux 环境下尤其实用。0.10 版本带来：更多 NVIDIA 超频控制——可管理 PowerMizer 最高 p-state 模式，并支持电压提升（让 GPU 升压到更高电压）；监控侧新增 Blackwell 热点（hot spot）传感器 支持与每颗显存芯片温度 传感器；此外改进了初始设置体验、可显示 AMD Radeon 的 GTT 内存占用，以及若干其他增强。
关注理由：LACT 是 Linux 显卡玩家实际离不开的工具之一。0.10 补齐 NVIDIA 超频档位/电压控制、并对最新 Blackwell 架构增加热点与逐显存温度监控，意味着在 Linux 下调校与观测新卡变得更顺手。对用 NVIDIA（尤其 RTX 50 系 Blackwell）或 AMD/Intel 显卡、又不想依赖闭源控制面板的用户，是即装即用的实用更新。
