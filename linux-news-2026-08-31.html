DXVK 3.1 发布：DXGI 增量呈现、D3D11 Buffer 渲染目标，Intel 显卡获厂商扩展支持
图形
Valve Steam Play（Proton）的关键组件 DXVK 3.1 今日发布——它是把 Direct3D 8/9/10/11 翻译到 Vulkan 的实现层。两大新特性：一是 DXGI 增量呈现（incremental presentation）支持，可修复一批 UI 渲染问题，对 Ubisoft Connect 等游戏启动器尤其重要；对支持 VK_KHR_incremental_present 的 Vulkan 驱动还有望提升效率。二是 Direct3D 11 buffer render targets——现在支持直接在 buffer 上创建 render target view，以适配 Battlefield 3 等老 Frostbite 引擎游戏。此外，Intel 显卡用户迎来厂商扩展支持：Intel GPU 上会加载 Intel 专用扩展库，思路类似已有的 NVIDIA NVAPI 支持，并将在未来 Proton 版本中继续扩展。
关注理由：DXVK 是 Linux 游戏兼容层的地基，其每次特性更新都会直接转化为 Proton 下的可玩性与画质。增量呈现直击长期困扰启动器/叠加层 UI 的渲染异常；Intel 开始提供类 NVAPI 的厂商扩展库，意味着 Intel 核显/独显在 Linux 游戏特性上正从「能用」走向「有专属优化路径」，与 NVIDIA/AMD 三足格局更完整。

Union QtWidgets 首个版本：KDE 统一样式引擎扩展到 QtWidgets 应用
显示
Union 是 KDE Plasma 6.7 首发的基于 CSS 的样式/主题引擎，目标是终结 KDE 应用样式方式长期碎片化的问题。今天 KDE 开发者 Akseli Lahtinen 宣布 Union QtWidgets 首个版本发布：Kate 编辑器、Dolphin 文件管理器等 QtWidgets 应用现在也能直接使用 Union 的 CSS 文件进行样式化。目前仍有一些已知样式问题（部分细节表现有偏差）正在修复。Lahtinen 强调：「这是有史以来第一次 Breeze 的 QtWidgets 与 QtQuick 样式拥有同一份可轻松编辑的共享单一事实源（配色方案除外）」——由于部分设计最初是为 QtQuick 考虑的，在 QtWidgets 下观感会略有出入。该支持预计随 KDE Plasma 6.8 发布。
关注理由：桌面 UI 一致性与主题定制一直是 Linux 桌面的隐性成本：QtWidgets 与 QtQuick 两套样式长期各自维护。Union 让二者共享同一份 CSS 源，既降低 KDE 维护负担，也让主题作者/发行版能用一套声明式文件统一整个桌面观感。对关注 Linux 显示栈与桌面工程化的开发者，这是 6.8 周期值得跟踪的架构级改动。

GNOME Mutter 的 GPU 重置恢复实现提交合并请求：会话可在 GPU 重置后存活
显示
Google Summer of Code 2026 的「GNOME Mutter GPU 重置恢复」项目近日收尾，学生开发者 Toluwaleke Ogundipe 今天发布了最终进展更新，合并请求（MR !5247，上周开启）已进入代码评审。实现被描述为「可靠（solid）」：Mutter 现在能够在 GPU 重置后存活并维持活动会话，会话状态可正确恢复——屏幕帧缓冲、窗口、光标与文本均已恢复；但 Shell UI 与桌面背景图尚未恢复，需要补充清理背景缓存以及纹理、主题节点缓存的代码才能让 Shell UI 元素重新加载。一些边界情况仍在排查，真实硬件测试也在持续进行中。
关注理由：GPU 挂起/重置在以往几乎等于「会话终结」，是 Wayland 合成器可靠性的经典痛点。GNOME 与 KDE 同期推进各自的 reset recovery，说明这已成为主流桌面的共同基线能力。对驱动开发者与做 GPU 压力/稳定性测试的场景，合成器侧的恢复能力直接影响调试效率与用户体验底线。

Vulkan 1.4.361 规范更新：新增 NVIDIA VK_NV_private_data_base_handle 扩展
图形
Khronos 以 Vulkan 1.4.361 收官八月。本次更新汇集了过去两周对 Vulkan API 规范的各种小修与澄清，包括改进 VK_EXT_descriptor_heap 的对齐限制等维护性内容。唯一的新扩展是 NVIDIA 的 VK_NV_private_data_base_handle：在分层（layered）环境下使用 Vulkan 时，用于获取底层 Vulkan device handle——当需要在 Vulkan layer 链之外直接与驱动通信时，此前没有标准化途径，该扩展提供了通道。它复用了 NVIDIA 驱动已有的「获取 device 基础句柄」能力。NVIDIA 的动机看起来主要指向自家的 Nsight 图形调试软件，但在日益壮大的 Vulkan layer 生态中也可用于其他场景。
关注理由：Vulkan layer 生态（调试、性能剖析、捕获、插帧/超分后处理）在 Linux 图形栈中的分量持续上升。为 layer 提供「穿透到驱动」的标准化句柄获取路径，既服务 Nsight 这类工具，也为第三方 layer 打开了直接与驱动交互的可能性——后续是否会有跨厂商的通用版本值得观察。

SteamOS 3.9 预览版：升级 Linux 7.2 内核与 KDE Plasma 6.7.3 桌面
显示 GPU
Valve 于昨晚放出适用于 Steam Deck、Steam Machine 等设备的 SteamOS 3.9 首个预览版。主要更新：Arch Linux 软件包基础整体刷新；桌面模式升级到 KDE Plasma 6.7.3（此前长期停留在 6.4.3），修复大量桌面体验问题；内核由 Linux 6.16 LTS 切换到 Linux 7.2 stable，带来更新的硬件支持与性能改进。此外还改用 WPA_Supplicant 改善 WiFi 处理、加入初步的系统休眠支持（尚未在 Game Mode UI 中暴露），并改进了以虚拟机 guest 运行 SteamOS 时的 VirtIO 图形加速支持。
关注理由：SteamOS 是 Linux 游戏图形栈规模最大的真实部署之一，其内核/桌面/Mesa 组合直接影响数百万设备的显示与图形路径。从 6.16 LTS 跳到 7.2，意味着较新的 DRM/KMS 与 AMDGPU 显示代码进入掌机主战场；Plasma 6.7.3 也把 HDR、色彩管理等新桌面显示特性一并带到位。

KDE Plasma 6.8 优化全屏内容性能与能效：色彩转换卸载到 CRTC，直通扫描场景更多
显示
本周 KDE 合入一组 Plasma 6.8 改进。核心一项是：在 Intel 或 NVIDIA GPU 上，当启用 HDR、ICC 色彩配置和/或夜览（night light）时，改善全屏内容的性能与功耗——做法是把 single-plane OETF 卸载到 CRTC 的 post-blend gamma LUT。这让更多场景能够走直接扫描输出（direct scan-out），而不是回退到着色器合成，同时减少色彩带状（banding），并更好地利用 DRM/KMS 硬件色彩管线。另一项 KPipeWire 改动让 Plasma/KWin 的屏幕录制延迟降低一帧。此外：回收站部件改用 KCoreDirLister 降低开销；修复了 Plasma 第二常见的崩溃（注销时 QConcatenateTablesProxyModel 析构崩溃）；内置 RDP 服务器可根据网络可用带宽自动调整画质。Plasma 6.7.5 则改进了使用 ICC 显示配置时 HDR 内容的观感。
关注理由：直接扫描输出是 Wayland 合成器降低延迟与功耗的关键路径，而 HDR/ICC/夜览一旦开启往往就会把它打断。把色彩转换卸载到 CRTC gamma LUT，等于在「要画质」与「要省电/低延迟」之间取得了更优解，也是把 DRM/KMS 硬件色彩管线真正用起来的范例——对笔记本续航与高刷桌面体验都有直接收益。

Linux 7.3-rc1 发布：Xe3P Nova Lake 开箱可用、新 AMD 图形 IP、Nouveau 支持 NVK Vulkan Video
内核 图形
为期两周的合并窗口结束，Linux 7.3-rc1 已可供测试。图形/硬件相关亮点包括：Intel Xe3P（Nova Lake）图形开箱即用，不再需要 force_probe；新 AMD 图形 IP 启用；Nouveau 支持 NVK Vulkan Video；Intel Starfire 初步使能；Apple M3 Ultra / Pro / Max 初步支持；Valve 针对显存（vRAM）极其有限系统的游戏改进；USB4STREAM 低延迟模式；以及对 Intel 混合架构 CPU 的新优化等。Linus Torvalds 在发布说明中特别指出：本次 rc1 提交数量虽大但并非史上最大，「真正让 diff 变大的原因是又一次 AMD GPU 寄存器大转储——这次是 AMD DCN6 寄存器头文件，它们非常庞大……总体而言，AMD GPU 代码与头文件约占整个 rc1 补丁的三分之一。」
关注理由：7.3 是本周期内图形侧合并最密集的一次：Intel 新一代 Xe3P 免参数启用、Nouveau 为 NVK Vulkan Video 铺路、AMD 新一代显示/图形 IP 落地，基本勾勒出未来半年 Linux 图形驱动的支持范围。Linus 关于「寄存器头文件撑大 diff」的吐槽也反映出 AMD 硬件定义头文件化的工程代价。

Linux 7.3-rc1 代码统计：内核逼近 4100 万行，AMD 图形/计算驱动达 652 万行
内核 图形
Phoronix 用 cloc 统计了 v7.3-rc1 的代码规模：内核总计 4098 万行（v7.2 为 4042 万行），其中代码行 30,937,090、注释 4,912,366、空行 5,134,418——按此趋势 Linux 7.4 将轻松超过 4100 万行。细分到 drivers/gpu/drm/amd（含头文件、AMDGPU 内核图形驱动、AMDKFD 计算驱动及相关显示代码，不含目录外的旧 Radeon DRM 驱动）：652 万行，v7.2 时为 635 万行。也就是说，现代 AMD 内核图形驱动代码已占整个 Linux 内核约 16%——膨胀的主因正是本周期新增的 DCN 6.0 等新 IP 寄存器头文件。
关注理由：这组数字直观量化了 AMD 图形+计算驱动在内核中的体量：单厂商单目录占到内核六分之一，且增速高于内核整体。对做内核图形/计算驱动、关注编译耗时与维护成本的团队，这是衡量「驱动复杂度通胀」的硬指标；AMDKFD 与 AMDGPU 共处同一目录也提示计算与图形栈在内核侧的深度耦合。

NVIDIA 基于 Vulkan 的帧率上转换 FRUC 合入 FFmpeg，走 Optical Flow 扩展路径
计算
本周末，FFmpeg 上游合入了基于 NVIDIA Vulkan Optical Flow 扩展的帧率上转换（FRUC, Frame Rate Up-Conversion）支持：通过插入插值帧把低帧率视频转换为高帧率视频，改善主观视觉观感。硬件侧自几年前的 Ada 架构起就提供该硬件加速能力，而上游 FFmpeg 现在通过 VK_NV_optical_flow（Vulkan 版本 Optical Flow）获得 FRUC 支持，具体依赖底层 Vulkan 驱动是否实现该扩展。代码以一系列 fruc_vulkan 提交于周六合入 FFmpeg Git。同期还一度合入了 NVIDIA RTX Video Filters 分支（RTX Dynamic Vibrance / DeepDVC、DLPP 超分、NGX 图像超分、Smooth Motion 补帧、RTX TrueHDR、RTX 视频超分等 CUDA 滤镜），但截至次日早晨该合并已从最新 FFmpeg Git 活动中消失，疑似被回退。
关注理由：值得注意的不是「NVIDIA 又多了个滤镜」，而是 FRUC 走的是 Vulkan 扩展而非 CUDA 私有栈——这意味着 FFmpeg 的 GPU 视频处理正在从厂商私有 API 向跨厂商的 Vulkan 路径迁移，其他厂商只要提供对应扩展即可接入同一框架。而 RTX Video Filters 分支的「合入即回退」也提示厂商大包提交在上游仍存在审查摩擦。

把 AMD ROCm 搬到 FreeBSD 有多难：LinuxKPI、下游 LLVM 与 HMM 三重关卡
计算
FreeBSD 基金会今年夏天的实习生项目致力于把 AMD 开源 ROCm 计算栈从 Linux 移植到 FreeBSD，本周发布总结（学生开发者 Sourojeet Adhikari）。FreeBSD 虽然已有从 Linux DRM 移植过来的 AMDGPU 驱动，也有 LinuxKPI 兼容层帮忙转换 Linux 内核接口，但工作量依然可观：不止内核改动——还需要给 ROCm 使用的 AMD 下游 LLVM 代码打补丁、调整 ROCm GPU runtime、修改 drm-kmod 模块，过程中还发现了 FreeBSD LinuxKPI 兼容接口自身的 bug 与行为差异。当前状态：项目已接近「跑通一个简单向量加法」的里程碑——驱动可以链接、加载并运行，用户态仍有问题待解；下一步将投入 FreeBSD 内存管理子系统的探索，尤其是支持 HMM（异构内存管理）所需的工作。实习期虽结束，该开发者计划继续推进。
关注理由：这份报告把 GPU 计算栈对操作系统的真实依赖拆得很清楚：驱动只是一层，LLVM 下游分支、runtime 与异构内存管理（HMM）才是跨 OS 移植的深水区。对做加速器/NPU 软件栈的团队，HMM 是统一地址空间与页迁移的基石，这里的经验对评估「自研驱动 + 自研 runtime 跨内核移植成本」有直接参考价值。
