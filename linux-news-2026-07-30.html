AMDGPU 为旧 AMD GPU 带来 DRM 格式修饰符（Linux 7.3，Valve 赞助）
GPU 显示 内核
在逼近下月 Linux 7.3 合并窗口的特性截止前，AMD 本周又向 AMDGPU 内核图形驱动与 AMDKFD 内核计算驱动推送了一批功能与改动。其中面向老旧 GCN 1.0/1.1（GFX6/GFX7）GPU 的 DRM 格式修饰符（format modifiers）支持尤为引人注目——这类显式描述缓冲区布局/tiling/压缩元数据的机制，是现代 Wayland/X11 合成器（gamescope、Weston、Mutter）与 Vulkan WSI 实现零拷贝扫描输出（scanout）的关键。HD 7000/8000、Sea Islands 等老架构仍被广泛使用，此前在 Linux 上缺乏完善的修饰符支持，限制了合成与串流效率。标题点名「Thanks Valve」，表明这项工作由 Valve 赞助，与其推动 Steam Deck / Proton / gamescope 跨 GPU 代际显示一致性的目标一致。
关注理由：DRM 格式修饰符是现代合成器/WSI 走零拷贝显示路径的底层基石；让仍存量巨大的 GCN 1.0/1.1 老卡也能享受现代修饰符语义，对 gamescope 串流与跨代 GPU 一致性意义重大，也体现 Valve 在开源图形栈上的持续投入。

Steam 客户端 Beta 新增 HDR 串流（Steam Deck OLED）+ AV1 视频串流
显示 计算
今日 Steam 客户端 Beta 更新为 Linux 玩家带来了两项串流增强。其一，Steam Deck OLED 机型新增高动态范围（HDR）串流支持，直接内化进最新 Beta 客户端；其二，Steam Deck 新增 AV1 视频串流——需配合实验性 SteamRT3 客户端使用，偏好用开放的 AV1 格式替代专有视频编解码器。两项之外还有若干修复，详见 Steam 客户端 Beta 发布说明。HDR 串流补齐了 OLED 掌机在远程畅玩时的高动态范围体验，而 AV1 串流则兼顾带宽与开放性。
关注理由：HDR + AV1 串流对 Steam Deck OLED 远程游戏体验是直接利好：HDR 还原高动态范围画面，AV1 以开放格式降低带宽并契合 Linux 玩家对开放生态的偏好；这类客户端侧改进无需内核/驱动升级即可惠及广大用户。

Intel 图形驱动为 Xe3 带来「峰值带宽阈值」省电特性（Linux 7.3）
GPU 显示
Intel 今日送出了为下月 Linux 7.3 合并窗口准备的最新一批内核图形驱动更新。对终端用户而言，本次特性拉取中最有趣的是 Xe3 Panther Lake 及更新架构上的「峰值带宽阈值」（Peak Bandwidth Threshold）省电特性：在 Xe3+ 上，当显示所需带宽低于最小 GV 点时，SoC 可以主动下调 fabric 频率；该阈值定义为 20 GB/s，驱动在「平台为 Xe3+、至少存在一个 QGV 点、QGV 点数量低于上限 8」的条件下新增一个 peak/derated 带宽均设为 20 GB/s 的 QGV 条目，当所需数据率低于 20 GB/s 时即选用该点。补丁未给出具体省电幅度。同期还启用了 Thunderbolt 隧道链路的 UHBR（超高比特率）链路速率、为支持 alpha 混合的平面添加 blend mode 属性及若干修复。
关注理由：这是 Xe3/Panther Lake 全新的功耗管理特性——显示带宽需求低时主动降 fabric 频率，对笔记本/掌机续航有现实意义；Thunderbolt 隧道 UHBR 与全平面 alpha 混合 blend mode 也拓宽了高带宽显示与合成能力。

Valve 赞助 Collabora 将开源 RADV Vulkan 驱动移植到 Windows
GPU 计算
Valve 正在赞助 Collabora 工程师开展早期探索性工作，试图把开源的 Radeon Vulkan「RADV」驱动带到 Microsoft Windows。RADV 是 Linux 玩家广用的开源 Vulkan 实现，也是 AMD 系 Steam Deck / Steam Machine 成功的重要部分。本次工作范围不包括把 AMDGPU Linux 内核驱动移植到 Windows，而是复用 AMD 官方 Windows 内核驱动——为此需要反向工程其专有内核驱动的数据结构，并可能通过稳定/有据的接口或 shim 库来跨驱动版本适配。Collabora 的 Louis-Francis Ratté-Boulianne 已发布博客，并演示了在 Windows 上用 RADV 跑起《Counter-Strike 2》；实验代码可在 freedesktop GitLab 的 wddm2 开发分支找到。
关注理由：用开源 RADV 挑战 Windows 上闭源厂商驱动，是跨平台开源 Vulkan 的重要一步；当 RADV 能在 Windows 跑起 3A 游戏，Steam Deck/Steam Machine 的图形栈一致性将不再受平台束缚，长远看会反哺整个 Mesa 生态。

YSERVER 1.4：Rust 编写的 AI 生成 X11 服务器，让 Steam / 全屏游戏跑起来（Cinnamon）
显示
YSERVER 是今年夏天登场、主要由 AI（Claude Code）编写的现代化 X11 服务器（Rust 实现），并持续补齐 X11 协议以让更多桌面环境/应用在其上跑起来。1.4 版的关键进展是让 Chrome 与 Steam 拿到 GPU 加速：GLX pixel buffer 现由真实 GPU pixmap 支撑，从而让 Chrome/Steam 获得 WebGL 加速；同时 KDE Plasma 的 RandR 调整尺寸与 ARGB 弹窗可用、Cinnamon 下全屏游戏与视频播放可用，KDE Plasma X11 分支 Sonic DE 也已测试通过。scanout buffer 现经 GBM 分配并导入 Vulkan，带来更好的驱动与 DRM 修饰符覆盖；此外还有 Present 与 vblank 对齐、键盘布局切换、RANDR 输出属性/EDID 透传、Xorg 兼容输出名、XI2 改进，以及 Fedora/Debian/Ubuntu/Alpine 的二进制包与 AUR。它已在 openSUSE Tumbleweed + NVIDIA 硬件上的 KDE Plasma 下通过验证。
关注理由：在「AI 辅助编写开源图形栈」的浪潮中，YSERVER 1.4 用真实 GPU pixmap 撑起 Chrome/Steam 的 WebGL、靠 GBM+Vulkan 提升 DRM 修饰符兼容性，既是 X11 存续的另类样本，也直观展示了 AI 生成代码撑起完整显示服务的可能性。
