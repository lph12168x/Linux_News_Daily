Imagination PowerVR 驱动将 BXM-4-64 MC1 GPU 标记为「已支持」，随 Linux 7.3 落地
GPU 显示 内核
本周发出的 drm-misc-next 补丁（面向 Linux 7.3 合并窗口）中，最值得关注的是 Imagination 的开源 DRM 内核驱动把 BXM-4-64 MC1 GPU 从此前的「实验性（experimental）」正式提升为「已支持（supported）」状态。这颗 GPU 出现在 T-Head TH1520 等 RISC-V SoC（如 Lichee Pi 4A、BeagleV Ahead 等开发板）上。此次转正是在配合 Imagination 的 Mesa Vulkan 驱动成功跑通 Vulkan 一致性测试套件（CTS）、并将 GPU 固件上游到 linux-firmware.git 之后达成的，意味着终端用户已可较为放心地使用这套完全上游、开源的 Imagination 驱动栈。同一批 drm-misc-next 还为 Tegra264 补充了 host1x/Tegra 驱动支持，并新增多款面板与若干修复。
关注理由：这是 RISC-V 平台开源 GPU 生态的重要里程碑——长期以来 RISC-V 板卡缺乏可用的开源图形加速，PowerVR BXM 转正让 TH1520 等国产/开源 RISC-V SoC 首次拥有经 Vulkan CTS 验证、完全上游的开源 GPU 驱动栈。对关注 Linux 图形驱动、RISC-V 桌面与嵌入式显示的用户，这条动态意义重大。

AMD ROCm 转向严格的六周发布周期：更快把新特性、性能优化与硬件支持交到用户手中
计算 GPU
本周 AMD Advancing AI 大会（旧金山）上传出的重要信息之一：ROCm 今后将采用固定的六周发布节奏。此前 ROCm 大致按季度推出 X.Y 特性版本，转为六周一发后能更激进地把新特性、性能优化和硬件支持更快送达用户。这一转变发生在 ROCm 7.14 发布之后——7.14 是首个基于全新构建基础设施「TheRock」的生产版本；此前 ROCm 7.9 至 7.13 均为「技术预览（tech preview）」版本。Michael Larabel 也在会上向 AMD 提出了 7.2 直接跳到 7.14 生产版这一「别扭」的版本号问题，AMD 暗示未来在版本命名上会有所调整，但暂无细节。下一个 ROCm 版本预计 8 月发布，并将随之带来此前宣布的 ROCm.AI 软件。
关注理由：ROCm 是 AMD 在 Linux 上的开源异构计算/AI 底座，其发布节奏直接决定新 GPU（如刚发布的 Instinct MI455X）与新特性能多快落到开发者手中。六周固定周期 + TheRock 新构建体系，标志着 AMD 在追赶 CUDA 生态成熟度上明显提速，对做 GPU 计算/AI 的 Linux 开发者是实打实的利好。

Snapdragon X Elite 笔记本在 Ubuntu 26.04 LTS 上体验进一步倒退：Adreno GPU 回落到软件渲染
显示 GPU
Phoronix 在 Ubuntu 26.04 LTS 发布后重新测试了搭载 Snapdragon X Elite 的 Acer Swift 14 AI 笔记本，结果比上一轮更令人失望。首先 Ubuntu 26.04 自带的 qcom-firmware-extract 版本 17 直接报「Device is currently not supported」，需手动从 26.10 开发仓库取版本 20 的 deb 才能从 Windows 分区提取 GPU 等固件。即便固件就位，系统仍回落到 LLVMpipe 软件渲染，而非真正启用 Adreno GPU——dmesg 显示 MSM DRM 驱动虽加载了固件，但在 GPU 硬件初始化阶段报错。作者尝试了社区的 Ubuntu Concept X1E PPA（linux-qcom-x1e 内核，停留在 4 月的 7.0.0-32.32）仍无济于事。要命的是同一台笔记本在 Ubuntu 25.04/25.10 上 Adreno GPU 本可正常工作，如今在 26.04 的 Linux 7.0 内核下反而回归失效；电池监控等也不工作（唯一好转是重负载下不再随机重启）。
关注理由：这是 Arm 笔记本 Linux 显示/图形支持现状的一记警钟：即便硬件此前可用，内核更新与固件工具链的脱节也可能造成 GPU 加速回归、跌回软件渲染。对关注 Snapdragon/Adreno、Arm64 桌面与 Linux 显示栈的用户，此文清晰呈现了 qcom-firmware-extract 与 MSM DRM 驱动当前的痛点。

AMD Advancing AI 2026：开放、开源、再开源——从开源驱动延伸到开放硬件
GPU 计算
在本周 AMD Advancing AI 2026 上，除了被反复提及数千次的「AI」，出现频率第二高的关键词就是「open（开放/开源）」。除了众所周知的 AMD Linux 图形驱动栈、ROCm 及其他开源驱动，本届大会还把「开放硬件」推到台前：新的 AMD Kria AI 软件开发平台主打开放，公开硬件原理图；同期宣布的 AMD Robotics Software Suite 亦开源，机器人开发套件上 FPGA 的 RTL 也一并开源；配套还推出被定位为最新开源生态的 AMD Robotics Partner Network。此外，AMD Helios 网络的软件栈基于开源的 SONiC（Software for Open Networking in the Cloud）构建，OpenBMC 继续在新的 EPYC 9006「Venice」服务器平台上发挥作用，OpenSIL（开源 CPU 硅初始化）也在 Zen 6 上达到生产状态。
关注理由：AMD 在数据中心 AI 硬件全面发力的同时，持续把开源/开放标准作为战略主线，从 GPU 驱动、ROCm 到 OpenSIL、SONiC、OpenBMC 乃至开放硬件原理图与 FPGA RTL。这种「开放优先」的取向直接惠及 Linux 开源生态与可维护性，与英特尔等厂商形成鲜明对照，值得关注开源图形/计算基础设施的用户留意其长期走向。
