AMD 准备在 Linux 下默认启用 HDMI 2.1 FRL：高刷/高分辨率显示器体验收官
显示 GPU
今年 5 月，AMD 意外地为其开源 AMDGPU 驱动提交了 HDMI 2.1 FRL 补丁（此前代码因 HDMI Forum 封禁多年，最终被解禁）。自 Linux 7.2 起该代码已进入主线内核，但因避免用户体验回退、需等 VRR 功能就绪而默认关闭。如今功能已成型，AMD 驱动工程师 Fangzhi Zuo 今日提交补丁，反转逻辑以默认启用 HDMI 2.1 FRL；如确需用于 bug/回退测试，仍可通过 amdgpu.dcfeaturemask 模块参数关闭。后续还进补了 DSC（显示流压缩）与VRR、ALLM 等游戏向特性。预计 Linux 7.4（今年晚些时候、定档为 2026 LTS 内核）有望同时具备 VRR 与 ALLM，7.3 周期已来不及。
关注理由：HDMI 2.1 FRL 是 4K/8K 高刷新率显示的带宽基石。对用 AMD Radeon 接 HDMI 2.1 显示器的 Linux 桌面/游戏用户，默认开启意味着无需手动改参数即可享受完整 HDMI 2.1 带宽与 VRR/ALLM 游戏特性。这是 AMD 在 Linux 下补齐 HDMI 2.1 体验的收官一步——7.4 若准时落地，将是 2026 LTS 内核送给 Radeon 用户的「圣诞礼物」。

AMD 从 ROCm 7.14 直接跃迁至 ROCm 10.0，引入 ROCm.AI 与六周发布节奏
计算 GPU
7 月发布的 ROCm 7.14 是基于 TheRock 构建系统、引入 Ryzen AI 400 支持的生产版本，但因 7.9+ 曾转为「tech preview」导致版本号混乱。为厘清，AMD 直接将 ROCm 大版本跃迁至 10.0，接替 7.x 成为开源 AMD Radeon/Instinct GPU 计算栈的最新主版本。最大亮点是新的 ROCm.AI（AI 驱动开发）与 ROCm CLI；同时转向六周发布节奏；引入 Hyperloom、更整合的 Linux 包、可用于 vLLM 的生产级容器与 Python wheels、Ryzen AI Max 本地 LLM 微调等。Windows 侧退役 HIP SDK，改用 ROCm Core SDK，并与 Linux 同步发布节奏。
关注理由：ROCm 版本号从此前混乱（7.2 稳、7.9+ 预览）一跃到 10.0，配合 ROCm.AI/CLI 与六周节奏，标志着 AMD GPU 计算栈走向工程化、产品化。对做 AMD Instinct/Radeon 加速计算、本地 LLM 推理的 Linux 用户，10.0 的 vLLM wheels + 容器直接降低部署门槛；Windows/Linux 同节奏也利好跨平台开发者。

Intel ANV 驱动修复 Vulkan Video H.265 解码：改用 HuC 固件、对齐 Vulkan spec
GPU
Intel ANV（Mesa Vulkan）驱动的 H.265 解码自 2023 年合入，但一直与 Vulkan spec 略有不符；今由 Igalia 的 Hyunjun Ko 在将合入 Mesa 26.3 的代码中修复：改为依赖 Intel HuC 微控制器固件。此前在录制期于 CPU 端解析码流，会违反 Vulkan spec（应用允许在录制后填充 buffer）。修复方式是发射 HuC S2L（short-to-long）序列，由 GPU 执行期从码流 buffer 解析 HEVC slice header 并写入二级 batch buffer；并通过 I915_PARAM_HUC_STATUS 探测 HuC 是否加载，决定启用/关闭 H.265 解码。多数系统 HuC 与 GuC 一并加载，无额外负担。
关注理由：这是 Mesa/Intel Vulkan Video 走向 spec 合规的关键修复——此前实现「能解但违规」，在严谨的 Vulkan 应用下可能出错。依赖 HuC 在 GPU 侧解析既合规又不增加用户负担。对用 Intel Arc/核显做 Vulkan 视频管线（转码、播放、推理前处理）的开发者，解码正确性与稳定性提升；也是 Intel 持续推进 ANV Vulkan Video 的延续。

Lemonade 11.8 让 DeepSeek V4 Flash 轻松跑在 AMD Strix Halo 上
计算 GPU
针对刚发布的 DeepSeek V4 Flash 模型，AMD 开发者发布 Lemonade 11.8，让其在 AMD Ryzen AI+ Max「Strix Halo」系统上一键跑起来。此前 Strix Halo 上跑 DeepSeek V4 Flash 需借助原生推理引擎 DwarfStar（ds4）；Lemonade 11.8 合入实验性 ds4 后端（PR #3047），对 Framework Desktop / Ryzen AI Halo 等机型大幅简化部署。11.8 还新增 RPG-HaloTales-V2 聊天模型、Flux-2-Klein-4B/9B 图像模型、OpenMOSS 语音设计与音效语音模型，并加入 lemonade update-models 命令便捷更新模型。
关注理由：Strix Halo（Ryzen AI Max+）高达 128GB 统一内存，是本地跑大模型的热门硬件。Lemonade 把 ds4 后端封装成易装的本地 AI 服务，让 DeepSeek V4 Flash 这类新模型在 Linux + AMD APU 上一键可用，是 AMD「本地 AI 软件栈」补齐体验的范例。对想用 Framework Desktop 等跑大模型的 Linux 用户，这是直接的易用性跃升。

LLVM 改进 Zen 1 / Zen 2 的 PDEP/PEXT 调度，应对「 notoriously bad」实现
计算
LLVM/Clang 工具链昨夜合入对近十年前 AMD Zen 1 及 Zen+/Zen 2 的更好支持：编译器工程师 Simon Pilgrim 改进了 PDEP/PEXT 标量指令调度。二者属 BMI2 位操作扩展（PEXT 并行位提取、PDEP 并行位沉积），用于数据库、密码学、象棋/Sudoku 等。znver1/znver2 的标量实现「notoriously bad」——仅用 WriteMicrocoded 标签无法体现其对 ALU 管道与 uops 洪泛的恶劣影响。由于 LLVM 临近开始生成 llvm.pdep/pext intrinsics（并标量化处理向量实现），Pilgrim 基于代价剖析完善调度，让 znver1/znver2 目标能做更明智选择（PR #217304 已合并）。
关注理由：这是「老架构 + 新编译器语义」的典型坑：当 LLVM 开始自动生成 pdep/pext intrinsic，旧 Zen 微架构的高代价实现会放大性能损失。提前补调度信息，避免老 Zen 用户在数据库/密码学/算法负载上被悄悄拖慢。体现 LLVM 对 AMD 全代际 CPU 的持续打磨，对仍跑 Zen 1/2（Ryzen 1000/2000/3000、EPYC Naples/Rome）的生产环境有现实收益。
