Linux 7.4 将合入 AVX-512 优化版 xor_gen()：软件 RAID 奇偶校验提速显著（Google 主导）
计算 内核
过去数月在社区流转的 AVX-512 优化版 xor_gen() 补丁现已排队，预计随 Linux 7.4 合入主线。该函数用于 Linux 软件 RAID 代码中生成与校验 RAID5 / RAID6 的奇偶校验块，此前已显示出相当可观的性能增益。这项由 Google 的 Eric Biggers 主导的工作，延续了他为 Linux 加密/校验代码引入 AVX-512 等现代 ISA 能力的一贯路线。受益对象为 AMD Zen 4 及更新、以及当前支持 AVX-512 的 Intel 服务器 CPU；公开基准基于 AMD Ryzen 9 9950X。最新第 5 版修订已在上周通过 TIP 的 x86/fpu 分支排队（commit c0a44d1），7.4 合并窗口在 10 月下半开启。
关注理由：对做计算/存储栈的团队，这条是「用宽 SIMD 指令重写内核热路径」的典型样本：xor_gen() 是软件 RAID 每个写操作都要走的校验内核，把它从标量/SSE 提升到 AVX-512 能在不换硬件的前提下拿到可观吞吐。启发有三：① 我们在 zeus 侧做数据搬运、校验、聚合类内核时，应系统性排查「仍停留在标量/窄 SIMD」的热点，宽 SIMD 的性价比往往高于加机器；② 值得关注 512 位向量在能效（频率回落、许可切换）上的权衡，避免只看峰值吞吐；③ 上游经验表明这类补丁通常要迭代 4~5 版才进主线，团队内部推动类似优化时应预留多轮评审周期。

AMD P-State 驱动将为 Zen 6 客户端 CPU 调优：三类核心 EPP 分别调参（瞄准 Linux 7.4）
计算
在 Linux 7.4 合并窗口前，针对 Zen 6 客户端 CPU 的 AMD P-State 能效偏好（EPP）调整已被提交。关键变化：ACPI EPP 在 Zen 6 客户端 CPU 上将表现出不同行为，并针对性能核与密集/能效核分别给出不同调参，同时纳入 AMD 新增的低功耗核心类型（该 core type 机制在 Linux 7.3 引入）。除三类核心使用不同数值外，驱动还改为由频率值计算 boost ratio，而不再使用任意的性能刻度。这批补丁随 AMD P-State 的其他修复一起通过 pull request 发往 Linux 电源管理子系统的 -next 分支，明确标记为 Linux 7.4。同期 AMD Radeon 侧，HDMI 2.1 也将在 Linux 7.4 默认启用（含 HDMI FreeSync、VRR、ALLM）。7.4 稳定版按进度可能于 12 月底发布，与传闻中 CES / 2027 上半年的下一代 Ryzen 上市节奏基本吻合。
关注理由：对做计算/能效调优的团队，这条的价值在于「异构核心的调度与调频已从内核通用逻辑下沉到厂商专属调参」：Zen 6 把核心分成性能核、密集能效核与新的低功耗核三类，EPP 需要按核心类型分别标定，这本质上和我们在 zeus 上区分加速器/通用核的能效策略同构。另外「boost ratio 从任意性能刻度改为按频率值计算」是一次从近似模型回到物理量的修正，提醒我们做功耗/性能建模时应尽量以频率、电压等可测物理量为基准，避免引入难以校准的经验刻度。

Ubuntu 26.10 将为 Intel Core 3 Wildcat Lake 笔电带来更好性能（Linux 7.2 + Mesa 26.2）
图形 计算
在 CHUWI UniBook（Intel Core 3 304 SoC、8GB 内存、256GB NVMe）这类低价笔电上，Ubuntu 26.04 LTS 已可开箱即用，而 10 月发布的 Ubuntu 26.10 会进一步释放性能。差异来自软件栈整体升级：内核从 Linux 7.0 升到 Linux 7.2，图形栈升级为 Mesa 26.2。本次对比使用截至 9 月 13 日的 26.10 开发版与打了全部稳定更新的 26.04 LTS。Ubuntu 26.10 beta 预计 9 月底发布，正式版 10 月 15 日。文章还预告将有后续一篇，专门探讨可选的 amd64v3 二进制对 Wildcat Lake 的影响；Intel Panther Lake 同样受益于这一轮升级。
关注理由：对做图形/计算栈的团队，这条把「发行版升级的实际收益拆成内核代际 + Mesa 代际两个来源」，是评估新硬件平台可用性的好参照：新低功耗 SoC 图形性能的大头往往不在首发，而在随后一两个内核与 Mesa 版本中释放。结合此前 Panther Lake 在 7.2→7.3 仍在增益的结论，可以给 zeus 相关平台的适配定一条经验线——把「图形栈版本代际」列为交付基线的一部分，并在选型评估中做跨发行版/跨 Mesa 版本的对照基准，而非只看单一发行版的首发表现。

Fedora 45 Beta 发布：KMSCON 取代内核控制台、GNOME 51、新增 DRM Panic 前端
显示 内核
Fedora 45 Beta 如期发布。显示与内核侧的重点：用 KMSCON 取代内核内控制台（in-kernel console，改为用户态控制台实现），并引入 DRM Panic 前端，在内核出错时给出更友好、更易用的显示界面。桌面为 GNOME 51。其余更新包括 Anaconda 安装器支持 Stratis 存储、默认限制 ptrace 以提升安全性、默认强制签名校验、并推进包构建可重现。工具链版本：GCC 16.2、LLVM 23、Glibc 2.44、Go 1.27、Python 3.15、RPM 6.1。正式版计划 10 月 20 日发布，兜底日期 10 月 27 日。
关注理由：对做显示/系统栈的团队，两个变化值得记下：① KMSCON 取代内核控制台，意味着控制台渲染从内核态搬到用户态、复用 DRM/KMS 路径，方向与我们做显示透明化、把复杂渲染逻辑留在用户态的原则一致；② DRM Panic 前端把内核崩溃信息变成可读画面，是「底层子系统直接参与呈现」的又一例证。同时注意 LLVM 23 / GCC 16.2 这类激进工具链版本配合默认 ptrace 限制与强制签名，会让用户态组件的编译与调试约束变严——我们为 zeus 准备发行版适配层时，需要把「默认安全策略收紧」当作显式的兼容性风险项来评估。

OpenAPV 1.1.1 发布：APV 专业视频编解码参考实现大更新（PBU 解码 + AVX2 / ARM NEON）
图形 计算
作为 Advanced Professional Video（APV）编解码器的开源参考实现，OpenAPV 1.1.1 发布，接替此前的 v0.3.0。版本号跨度较大是因为项目采用 APISET.MAJOR.MINOR.PATCH 方案：v0.3.0.0 是 API set 0 的收官版本，本次是首个携带 API set 1 的版本，而 API set 0 完全保留、未做任何删除，仍受支持。新版本引入基于 PBU（Primary Block Unit）的解码；新增使用更小 tile 的 profile，以更好利用并行度并支持更细粒度的部分解码。此外新增自定义内存分配器支持，可让编解码器脱离 C 库堆；并加入新的 AVX2 与 ARM NEON 优化、SIMD kernel 代码清理与健壮性改进。项目由 Academy Software Foundation 托管，后续将在不同硬件上公布 APV CPU 基准。
关注理由：对做图形/媒体栈的团队，APV 瞄准的是专业级（近无损、帧内、高色深）制作流程，而 OpenAPV 1.1.1 的三个动作都指向可并行性与内存可控性：更小 tile 提升解码并行度、PBU 解码细化粒度、自定义分配器把内存受控权交回上层。这与我们在 zeus 上把多媒体编解码从通用堆搬到自有内存管理、并追求片内并行的思路高度一致。另一个可借鉴点是它的API set 版本策略——通过「API set 递增 + 旧集合完全兼容」实现大版本演进而不破坏既有集成，比语义化大版本断裂更适合被长周期产品依赖。

SDL3 上游新增 HarmonyOS / OpenHarmony 支持：已合并进上游 SDL Git
图形
广泛用于游戏与应用的跨平台软硬件抽象库 SDL3，现已获得对华为 HarmonyOS / OpenHarmony 的上游支持。这项工作由知名 Linux 游戏移植者 Ryan "Icculus" Gordon 完成，由游戏工作室 Outfit7 赞助。HarmonyOS 是华为面向手机、平板、PC、智能设备等开发的分布式操作系统，采用微内核设计；OpenHarmony 则是其开源分布式系统分支。据 Icculus 介绍，该移植已在真实硬件上测试通过，并已有商业游戏在实际使用，且自即日起已合并到上游 SDL Git（PR #16281）。
关注理由：对做图形/游戏栈的团队，这条的意义在于「跨平台图形抽象层多覆盖一个操作系统」所释放的杠杆：SDL3 一并抽象了窗口、输入、音频、GPU（Vulkan/Metal/D3D 等后端），它一旦支持某个平台，上层引擎与游戏就能以极低成本进入。我们评估 zeus 的软件生态时，应把「是否被 SDL/SDL_GPU、Vulkan、FFmpeg 这类事实标准抽象层覆盖」作为比自研 SDK 更硬的采纳门槛；同时「由社区移植者 + 一家游戏工作室赞助完成、并直接上游合入」这种低成本落地路径，也值得作为推动外部生态适配 zeus 的参考范式。
