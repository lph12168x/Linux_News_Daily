VKD3D 2.1 发布：上游 Wine 的 Direct3D 12 → Vulkan 再进化
图形
CodeWeavers 的 Henri Verbeet 发布了 VKD3D 2.1，作为上游 Wine 项目将 Direct3D 12 通过 Vulkan API 实现的组件。2.1 在 HLSL 着色语言支持上带来多项新特性与改进：新增 dead store elimination（死存储消除）优化通道，使常量表布局更贴近 Direct3D 编译器；附以更严格的校验及其他增强；并继续强化对遗留 Direct3D 字节码源的支持。更新后的 VKD3D 其 SPIR-V 目标现支持浮点转 64 位有/无符号整数转换操作（对 DXIL 源很有用），同时对 GLSL（OpenGL 着色语言）目标支持也做了多项改进。更多改动细节见 WineHQ 的 2.1 发布公告。
关注理由：VKD3D 是把 Windows 平台 Direct3D 12 游戏/应用带到 Linux（Wine/Proton）的核心桥梁。2.1 在 HLSL 编译质量（死存储消除、常量表布局对齐 D3D 编译器）与 DXIL 转换能力（64 位整数转换）上的改进，能减少着色器翻译误差、提升兼容性与稳定性。对 Linux 游戏与 D3D12 应用生态，这是上游 Wine 图形栈的务实进展。

Intel 提出 DRM Fabric：面向 GPU/AI 加速器的厂商中立互连拓扑
计算
在 AMD 刚发布庞大 UALink 内核补丁系列数天后，Intel 工程师提出了一个名为 DRM Fabric 的提案。它旨在成为面向 GPU 与 AI 加速器 scale-up 互连的、厂商中立、协议无关的 DRM 拓扑基础设施，与 UALink 或 AMD xGMI 互补。其数据模型为 fabric → endpoint → port → peer：fabric 聚合一个 provider 定义的互连实例的端点；endpoint 是一个加速器挂接（持有物理端口）；port 上报通道能力、运行状态与可选计数器；peer 是命名直接相邻加速器或交换端口的带类型值（非活内核对象引用）。核心只记录直接邻接，端到端可达性与交换转发仍留给 fabric 控制器。它通过 Generic Netlink 暴露多对象、事件驱动的 uAPI（YAML 描述），而非 sysfs；当前为 RFC，前 6 个补丁构成只读里程碑、可独立合入，7–12 补丁加入特权 provisioning。Intel 在塑形 provider API 时参考了公开可用的 AMDGPU xGMI 实现；推测与即将到来的 Crescent Island AI 加速器有关。目前尚未定义数据传输、交换策略、热迁移、MMU 编程等，也无生产级 provider 实现。
关注理由：开源/Linux 上 GPU 与 AI 加速器互联正快速标准化。AMD 的 UALink 内核补丁（8/21，已于本期更早报道）与 Intel 的 DRM Fabric 提案同周出现，意味着 scale-up 互连正在形成「厂商中立基础设施」。DRM Fabric 把拓扑与控状态纳入 DRM 统一管理，为未来多厂商加速器集群在 Linux 上的互操作与运维（拓扑发现、邻接、端口统计）打下内核基础，对构建开放 AI 训练/推理集群的开发者是方向性信号。

Firefox 157 计划默认启用 JPEG-XL 图像解码，Chrome 同步推进
显示
虽然 Firefox 152+ 已提供实验性 JPEG-XL 支持，Mozilla 今日正式公布在 Firefox 浏览器中正式交付 JPEG-XL 图像格式支持的计划。目标版本 Firefox 157（预计 9 月底发布）将在所有可用平台上默认启用 JPEG-XL 图像解码；目前 Firefox Nightly 已默认开启以协助验证，Mozilla 认为支持已足够成熟可在稳定版首秀。与此同时，Google 也正式化了其意图：在 Blink 引擎中默认对所有用户启用 JPEG-XL 解码。JPEG-XL 在无损图像、渐进式渲染、以及在不损失质量的前提下进一步压缩 JPEG 方面表现出色，而 AVIF 在 web 质量照片与混合边缘/平面图像上更小——对超大图像，为渐进式渲染能力接受稍大文件体积而选 JPEG-XL 是合理权衡。
关注理由：JPEG-XL 历经 Google 反悔又重启的波折后，终于在两大浏览器引擎（Firefox 157 默认 + Chrome/Blink 默认）上同时落地，标志这一高效图像格式在 Web 上迎来真正的可用拐点。对 Linux 桌面/网页渲染与图像管线而言，原生高效的 JXL 解码意味着更省带宽、更快渐进式加载、更好的无损/再压缩体验，也呼应了此前 Firefox 153 已带来 Vulkan 视频解码与实验性 JXL 支持的路线。
