AMD P-State 驱动新补丁：游戏 1% Low 帧率最高提升 31.8%
计算 内核
Meta 内核工程师 David Vernet 向 Linux 内核邮件列表提交了一组 AMD P-State 驱动补丁，为「近期繁忙」的 CPU 核心实现按核（per-core）EPP（能效偏好）动态加速。当前 EPP 主动模式下，游戏主线程/渲染线程每帧都会在 futex 或 GPU fence 上短暂阻塞，每次睡眠都会衰减硬件的性能信号，导致唤醒后从低频起步、帧时间尾部延迟被放大。全局强制 EPP=performance 会烧掉掌机上 CPU/GPU 共享的功耗预算；抬高 min_perf 又会在微空闲期钉死频率、反而干扰 SMU 的 CPU/GPU 联合加速管理。新方案为可选（amd_pstate.epp_boost=1）的按核 EPP boost：每 10ms 采样一次核心 C0 占用率（MPERF/TSC 增量），若达到 50% 繁忙即把该核 MSR_AMD_CPPC_REQ 的 EPP 字段设为 performance，300ms 无繁忙采样后恢复。在 Valve Steam Deck 上实测《文明 6》：1% Low FPS 提升 31.8%，p99 帧时间改善 4.1%。补丁尚待 AMD 工程师评审，有望惠及所有 AMD 掌机与桌面平台。
关注理由：1% Low 帧率是游戏流畅度的关键指标，31.8% 的提升幅度对 Steam Deck 等功耗受限掌机意义重大；「按核短时 EPP boost」在能效与尾延迟之间走出的新路径，也可能成为 Linux 游戏调频策略的通用范式。

Starling：用 Swift 编写的全新 Linux 桌面，自带 Wayland 合成器与内置 X11 服务器
显示
开源桌面阵营再添新丁：Starling 是一个主要借助 Claude（AI/LLM）编写的全新 Linux 桌面环境——桌面部分使用 Swift 语言开发，配套一个以 C 实现的自研 Wayland 合成器，还内置了 X11 服务器用于承接 X11 客户端程序，无需依赖 XWayland。在「AI 大规模辅助编写开源项目」的浪潮下（此前已有约 2.5 万行纯汇编的 Frame X11 服务器、Swift 写的其他桌面试验），Starling 展示了非传统技术栈 + AI 辅助快速构建完整图形栈组件的可能性。项目仍处早期阶段，距离日常可用尚有距离，但其「桌面 + 合成器 + X11 兼容层」三合一的自包含设计在新兴桌面项目中颇为少见。
关注理由：继 Frame（汇编 X11 服务器）之后又一个 AI 辅助编写的图形栈项目，Swift 进入 Linux 桌面/Wayland 合成器领域本身就是罕见样本；自带 X11 服务器而非依赖 XWayland 的设计也提供了观察 Wayland 兼容层多样化实现的窗口。

Ryzen AI 9 HX 470 四系统横评：CachyOS 领先 Windows 11 约 11%，微幅胜出 Ubuntu/Fedora
计算 GPU
Phoronix 在 BOSGAME VTA-439 迷你主机（全新 AMD Ryzen AI 9 HX 470「Gorgon Point」SoC：12 核 24 线程 + Radeon 890M RDNA 3.5 核显、32GB DDR5-5600、1TB NVMe）上进行了 Windows 11 Pro、Ubuntu 26.04 LTS、Fedora Workstation 44 与 CachyOS 的开箱即用四系统横评。近 100 项基准的几何平均结果：三大 Linux 发行版相当接近，CachyOS 仅比 Ubuntu 26.04 快约 1%（不及其以往的显著领先幅度），但相比 Windows 11，CachyOS 在同一硬件上快约 11%。Llama.cpp AI 推理在 Vulkan 后端下 Linux 普遍更快，但 CPU BLAS 后端个别场景 Windows 反而占优，与此前其他平台的观察一致。
关注理由：Gorgon Point（Zen 5 刷新）新 SoC 的 Linux 开箱表现是新硬件支持成熟度的直接检验；「Linux 比 Windows 快 ~11%」与「激进优化发行版领先幅度收窄至 1%」两个数据点，对追求计算/AI 推理性能的用户选择发行版具有参考价值。
