NVIDIA 615.71.09 Linux 驱动发布：Vulkan 改进 + 开源内核驱动终于支持 cgroups 显存分区
图形
NVIDIA 今日发布 R615 系列 615.71.09 Linux 驱动，重点是 Vulkan 侧的若干改进：新增 VK_NV_low_latency 修订版 2，让 Vulkan 原生游戏开箱即用 Proton 下的 NVIDIA Reflex；新增 VK_EXT_cluster_acceleration_structure 扩展；并修复了 NVIDIA Smooth Motion 的启动与 Alt-Tab 卡死、Wayland 下加载 PRAGMATA 的 Xid 错误。还新增内核参数 RmDisableDisplayGlitchPerfLimit，可在部分多屏配置下降低待机功耗。更值得关注：开源内核驱动终于支持基于 cgroups 的显存分区（memory partitioning）。
关注理由：对做图形/驱动的团队，这条有两点直接可对照：① VK_NV_low_latency v2 让 Proton 下 Reflex 开箱即用，意味着 Linux 游戏低延迟路径在 Vulkan 层打通，可对照我们在 zeus 上「呈现时序/延迟由谁主导」的设计；② 开源驱动支持 cgroups 显存分区是老需求落地——多租户/多容器共享 GPU 时按 cgroup 隔离显存，与我们「加速器显存切分与隔离」的诉求高度一致，值得跟进其内核态实现方式。

实验补丁让 Nouveau+NVK 跑通 NVIDIA DGX Spark GB10（Grace Blackwell 超级芯片）
图形
Red Hat 的 David Airlie 让逆向内核驱动 Nouveau 与 Mesa NVK Vulkan 驱动在 GB10 Grace Blackwell 超级芯片 / DGX Spark 上跑了起来。内核侧把 Nouveau 适配到较新的 NVIDIA R610 固件（NVIDIA 不保证固件跨版本兼容，此步本身即是工程 feat），并重写显示代码、修 vRAM/L2 cache 处理、补 Spark 专属启动与显示支持；NVK 侧则补了深度/模板缓冲与 vRAM 差异处理。整套 bring-up 约 100 个补丁、改动侵入性强，Airlie 也坦言 GB10/DGX Spark 支持或许该等到 Nova 驱动转型。
关注理由：对做图形栈的团队，这是「开源驱动啃新一代 Blackwell 架构」的真实进度条：R610 固件适配 + 显示代码重写 + vRAM/L2 处理，几乎每一步都是我们在新加速器 bring-up 上也会踩的坑（固件兼容性、显存层级、显示链路）。它和 Nova 驱动的此消彼长也提示：新架构上「继续逆向 Nouveau」还是「等 Nova」是必须早做的技术路线抉择，对我们选型有借鉴意义。

XWayland 26.1 RC2 发布：自 XWayland 24.1 以来首个大版本，RC2 再修一批问题
显示
XWayland 26.1 是继 2024 年 XWayland 24.1 之后首个重大更新。整体带来更好的 rootful 实现、与 X Input 2 的多席位（multi-seat）兼容、对新 Wayland 协议的支持、更好的 Resize and Rotate（RandR）模拟，并彻底移除 EGLStream 支持。本次 RC2 再补多项修复：多个 XKB 修复、damage tracking 改进、X Input 的 字节序交换（byte-swapping）修正等。同期 X.Org Server 26.1 也在推进，是比 xorg-server 21.1 系列更大的更新。
关注理由：对做显示/合成器的团队，XWayland 26.1 的「rootful 改进 + multi-seat + 移除 EGLStream」是 X11 兼容层与现代 Wayland 收敛的关键一步：EGLStream 移除意味着 NVIDIA 旧显示路径彻底退出历史舞台，统一到 GBM/EGL；RandR 模拟与 multi-seat 改进则直接影响多屏/多用户场景。可对照我们在 zeus 显示栈上「X 兼容层与 Wayland 原生路径如何取舍」的边界划分。

YSERVER 1.5 发布：Rust 重写 X11 服务器带来 Reverse PRIME 多 GPU 支持
显示
用 Rust 从零实现的现代 X11 服务器 YSERVER 发布 1.5，已能跑 Cinnamon、MATE、Xfce、Openbox、IceWM 等真实桌面。本次最大亮点是 Reverse PRIME 支持：主 GPU 负责渲染、再把画面交给副 GPU 输出，并补齐了 DRM 设备到 Vulkan GPU 的映射与 RandR provider 拓扑暴露。另含 Mesa OML MSC 速率查询（修 ANGLE/Flatpak 报错）、桌面 accel-profile 设置、DRI3 1.4 同步对象经 DRM 传递、X11 服务端窗口边框等。还修了一个回归：解除了 vsync-off 客户端的帧率封顶——CS2 在 yserver 上测得 180~200 fps、Xorg 约 400 fps，根因是 07-27 的 vblank-pacing 闸门（NVIDIA-WSI 特有的 sync 呈现路径未实现）。
关注理由：对做显示/多 GPU 的团队，YSERVER 的 Reverse PRIME + DRM→Vulkan GPU 映射正是「多 GPU 渲染/输出分离」的活样本：主卡渲染、副卡扫描输出这套拓扑，和我们「offload/呈现分离」的思路一致；而它踩到的 vsync-off 帧率封顶（NVIDIA-WSI 的 PresentOptionAsync 差异）也提醒：同样是「关垂直同步」，Mesa 与 NVIDIA 的 WSI 呈现语义不同，做多厂商显示兼容时这段差异必须显式处理。

Steam 客户端 Beta 更新：大画面模式增强 + 多项 Linux 改进
图形 计算
Valve 发布大型 Steam 客户端 Beta：大画面模式（Big Picture Mode）新增「Big Art Mode」首页选项、首页「推荐」页个人日历、以及支持自定义屏保的屏保功能。通用改进含启动性能与 Steam Input 运行时 CPU 占用下降。Linux 侧：高延迟连接下下载提速、桌面 UI 现会显示 SteamOS 兼容性对话框（安装未验证游戏时）、安装已知不兼容 Proton 的游戏时弹「SteamOS 不支持」提示、SteamRT3 实验 Beta 多项修复，并改进了 Steam 调查用的 Linux 发行版信息收集。
关注理由：对做 Linux 游戏/图形生态的团队，Steam 客户端 Beta 的 Linux 改进（下载提速、Proton 兼容性提示、SteamRT3 运行时修复）是 Valve「把游戏体验压到 Linux 原生」的持续推进——其中 Proton/兼容层提示逻辑直接关乎我们「游戏/AI 应用能否在 Linux 加速器上顺畅跑」的验证链路；SteamRT3 运行时修复也提示运行时容器化的稳定性仍是高频打磨点。

System76 推出 Thelio Mira AI：AMD Ryzen + NVIDIA/AMD 多 GPU 的 Linux AI 工作站
计算
System76 发布 Thelio Mira AI 桌面工作站，面向 多 GPU AI 训练、模型微调、推理、计算机视觉与图像生成，也可用于仿真等 HPC 负载。沿用 Thelio Mira 机箱与 AMD Ryzen 9000 系列平台（Ryzen 7 9700X / 9 9900X / 9 9950X），但增加 GPU 选项与低功耗 CPU 以释放更多给 GPU 的供电余量。GPU 最高可选 AMD Radeon AI PRO R9700 或 NVIDIA RTX PRO 6000，预算充足可上 双 RTX PRO 6000；标配 64GB 内存（可至 192GB）。起价 3,299 美元。
关注理由：对做计算/AI 加速的团队，Thelio Mira AI 是「AMD CPU + 双 NVIDIA/AMD 顶级 GPU」商用多卡工作站的现成参考：多 GPU 供电、散热与内存带宽规划，正是我们部署 zeus 类加速器时要权衡的硬件拓扑；同时它把 AMD Radeon AI PRO 与 NVIDIA RTX PRO 并列可选，也提示 Linux 上多厂商 GPU 混部（ROCm vs CUDA）正成为工作站常态，软件栈的跨厂商兼容值得提前布局。
