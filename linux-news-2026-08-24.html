Linux 7.3 DRM 图形驱动改进：从老卡到次世代硬件
图形
Linux 7.3 的 DRM 子系统合并窗口已合入，GPU 内核驱动迎来一波从老卡到次世代硬件的广泛改进。Valve 的 Natalie Vock 主导的 DMEMCG 显存驱逐让 vRAM 超额使用时游戏性能更稳（已先在 SteamOS 上线，初期对 AMDGPU 与 Intel 图形均生效）；Valve 的 Timur Kristóf 为 GFX6–GFX8 老 AMD 显卡加入 DRM 格式修饰符支持，配合改进的 GPU reset 恢复，让初代 GCN 老卡在现代合成器下更可用。AMDGPU 还启用了现代 APU 的第二图形管道、8K 显示修复、DCN 6.0 显示核心与 DC CACP 省电。Intel 侧 Xe3P Nova Lake S 核显被认定为稳定并默认启用（移除 force_probe）。开源 NVIDIA 路线：Rust 版 Nova 驱动获得 Blackwell/Hopper 修复与 GSP 启动改进（含 vGPU 启用 GSP 启动），Nouveau 的 NVDEC 支持则为 NVK Vulkan Video 铺路；TTM 也更激进了。
关注理由：这是 7.3 图形栈的总览式更新：既照顾初代 GCN 老用户（格式修饰符零拷贝、reset 恢复），又推高次世代（Nova Lake 稳定、DCN 6.0）。结合本周 RDNA 4m 固件就位，对判断 Linux 7.3 是否值得升级、以及开源 GPU 驱动成熟度，这是关键一期。

AMD RDNA 4m 固件发布，Linux 上市前就绪
图形
AMD 本周五在向内核提交 UALink 启用补丁的同时，还将 RDNA 4m（GFX 11.7）所需的全部固件二进制上传到了 linux-firmware.git 仓库。RDNA 4m 介于 RDNA 3.5（GFX 11.5）与 RDNA 4（GFX 12.0）之间，「M」可能指代移动平台；其驱动代码早已贯穿 AMDGPU 内核驱动、AMDGPU LLVM 着色器后端，以及 RadeonSI 与 RADV。本次固件包含 GFX 11.7.0 与 11.7.1（尚无 11.7.2）、PSP 15.0.0/15.0.9 安全固件、SDMA 6.1.4、VPE 2.0.0 视频处理引擎与 DCN 4.2 显示核心。按 IP 版本推算，RDNA 4m 将带来新视频处理引擎与 Display Core Next 4.2 显示能力；预计 Linux 7.3 内核 + Mesa 26.2~26.3 是其良好基线。
关注理由：固件是开源驱动「开箱即用」的最后一块拼图。AMD 这次罕见地在硬件上市前就把固件推入 linux-firmware.git，意味着发行版可在发布时打包、用户上市即可获得良好体验。对追踪 AMD 下一代移动显卡在 Linux 上落地节奏的人，这是一个明确的就绪信号。

NVK Vulkan Video 合入 Mesa 26.3
图形
Mesa 的开源 NVIDIA「NVK」Vulkan 驱动迎来重磅新特性：Vulkan Video 初始支持已合入 Mesa 26.3-devel，首发支持 H.264 解码。由于需要对 NVIDIA 视频加速的部分处理逻辑做逆向工程，且部分实现用 Rust 编写、需等待 Rust 驱动基础设施成熟，这一特性历经数年才落地。H.265 解码的工作也在推进，但目前会让 NVIDIA GSP 卡死，故暂时仅 H.264 可用；由于依赖 GSP，仅 Turing 及更新的 GPU 支持 NVK Vulkan Video。该用户态驱动还依赖本周合入 Linux 7.3 的 Nouveau NVDEC 补丁作为内核前提。Mesa 26.3 将于 Q4（约 11 月）作为稳定版发布，大致与 Linux 7.3 稳定版同期。
关注理由：这是 Mesa 开源 NVIDIA 驱动在视频加速上的关键里程碑：此前 NVK 在视频编解码上明显落后于闭源驱动，Vulkan Video 的合入让 Turing+ 用户能在纯开源栈下做 H.264 硬解。它与本周 DRM 的 Nouveau NVDEC 改动是配套工程，标志着开源 NVIDIA 图形/视频栈进一步逼近闭源能力。

开源 Etnaviv 驱动现在能跑 YOLOX 目标检测
计算
开源、逆向工程的 Etnaviv 驱动栈（最初为 Vivante GPU IP 提供加速图形，后扩展到 Vivante NPU）如今能在嵌入式 NPU 上跑 YOLOX 目标检测模型。主导 Etnaviv AI/NPU 工作的开发者 Tomeu Vizoso 在 Vivante VIP 系列 NPU（如 NXP i.MX8M Plus 搭载的型号）上点亮了 YOLOX，能力显著强于此前的 SSDLite MobileDet。随着 Etnaviv 驱动补齐了更多算子与改动（结合 Mesa 的 Teflon 框架），YOLOX 已可作为该逆向驱动栈的旗舰模型成功运行。
关注理由：Etnaviv 把开源 GPU/NPU 加速从「能图形」推进到「能跑现代目标检测模型」，对无独立 NPU 的嵌入式 Linux 设备（如 i.MX8M Plus）意义重大：无需闭源 blob 即可在本地做边缘 AI 推理。这是开源嵌入式 ML 栈在真实硬件上可用性的重要一步。

KDE Plasma 6.8 本周落地多项性能优化
显示
本周的 This Week in Plasma 展示了迈向 Plasma 6.8 的进展（软冻结 8/27、Beta1 9/10、Beta2 9/24、6.8.0 目标 10/14）。性能方面：KWin 的 GPU reset 通知现在会触发所有 GPU 而非仅主 GPU；Discover 的后台更新检查进程内存占用「大幅减少」；Plasma 启动因避免不必要的壁纸加载工作而略快；KWin 截图功能更快、高刷新率屏幕下的录屏更顺滑；KDE Frameworks 6.30 改进了 SVG 缓存，带来更快速度与更低的 vRAM 占用。另外 Breeze 主题改善了 GTK4 应用的菜单与窗口边框样式，锁屏也优化了按钮对齐与可选认证方式。
关注理由：Plasma 6.8 在暑期仍在密集打磨：多 GPU 的 GPU reset 通知、SVG 缓存降低 vRAM、录屏/截图在高刷屏更顺滑，都是直接影响日常桌面流畅度与稳定性的改进。对关注 KDE Wayland 合成器体验、尤其是多显卡与高刷用户的开发者，这是一期的实用进展汇总。

Wine 11.16 发布：VA-API 硬件解码 + 更好的 ARM64 支持
显示
Wine 11.16 作为双周开发版发布，最大亮点是用 VA-API（Video Acceleration API）实现硬件加速视频解码：CodeWeavers 的 Elizabeth Figura 为 WineD3D 实现了 VA-API 后端到 D3D 视频解码，当前支持 H.264 解码（尚不支持 H.265 等）。ARM64 方面：更新的 Wine Mono 引擎现已支持 64 位 ARM，ARM64EC 上的异常处理也得到改进。本期还带来 35 个已知 bug 修复（涉及《命令与征服 3》、Steam 客户端、Siemens 自动化软件与 regedit 等），并修复了围绕 $WAYLAND_DISPLAY 处理的 Wayland 问题。这是迈向 Wine 12.0 稳定版路上的节点。
关注理由：Wine 在 Windows 应用/游戏的 Linux 视频路径上补齐了硬件解码这一长期短板：VA-API 后端让 D3D 视频走 GPU 硬解，对播放类应用与游戏内视频省 CPU、降功耗。ARM64 的 Wine Mono 64 位与异常处理改进，则利好在 Apple Silicon / 骁龙等平台上跑 Windows 软件的桌面用户。

AMD 提交庞大补丁系列，在 Linux 内核启用 UALink
计算
AMDGPU 维护者 Alex Deucher 在周五向内核邮件列表发出两套补丁，为开源/Linux 引入 UALink 基础设施。Ultra Accelerator Link 是用于在数据中心 scale-up pod 内连接 GPU 与其他 AI 加速器的开放标准高速网络协议，设计上可在一个域内连接多达 1024 个加速器。第一套补丁共 95 个、约 7k 行代码，加入核心基础设施与 AMDGPU 内核图形驱动集成；第二套仅 3 个补丁，暴露新的 IOCTL 接口与相关文档。其关键特性：pod 内 GPU 可通过 UALink 直接加载/存储远端显存（不像 RDMA 需要拷贝，是 fabric 上的直接访问），共享地址空间称为 NPA（Network Physical Address），每个 GPU 维护类似 GPUVM 的页表；被导出内存不固定，导出方在 TTM 驱逐或 MMU notifier 时通过远端 TLB 失效来协调；节点掉线/重置时对等方会清理丢失的引用。
关注理由：UALink 是 NVLink 的开放替代、AI 集群 scale-up 的关键互联。AMD 这次把核心内核支撑与驱动集成率先开源，意味着未来 Instinct 等加速器在 Linux 上的跨卡显存直访将有标准路径，对构建开放 AI 训练/推理集群的开发者是基础性进展。

Intel Compute Runtime 26.31.39395.13：备战 Crescent Island 与 OpenCL LEO
计算
Intel 今日发布开源 GPU 计算栈 Compute Runtime 26.31.39395.13（面向 Windows 与 Linux）。持续主线仍是为次世代企业级 AI 推理加速器 Crescent Island 做准备：本期同步了更多 Crescent Island 设备 ID（暗示多 SKU）、Crescent Island 的 media handle 支持、默认启用统一系统内存（USM）等；同时围绕随 Nova Lake 到来的 Xe3P 核显做了多项细化。今年早些引入的实验性 LEO 实现（构建于 Level Zero API 之上的新 OpenCL 实现）继续完善，仍为实验性但功能渐丰。本期还新增 cl_intel_bfloat16_conversions 扩展支持与 Linux 内核模式驱动 wait-for-event-host 同步。
关注理由：Compute Runtime 的每次更新都是 Intel GPU/SYN 计算生态成熟的晴雨表：Crescent Island 设备 ID 持续补齐说明这款企业级 AI 推理加速器的 Linux 支持正临门一脚，而 LEO 作为 OpenCL 在 Level Zero 之上的现代化重写，关系到 Intel 计算栈长远的架构走向。对做 Intel GPU 上 AI 推理的开发者，值得跟踪。

Intel 计算机视觉感知驱动已就绪支持 Nova Lake
图形
Linux 7.3 的媒体子系统合并中，此前在 7.2 合入的 Intel 计算机视觉感知（CVS）驱动本周期扩展支持次世代 Nova Lake 平台。Intel CVS 驱动是一个 V4L2 子设备，用于管理 Linux 与固件之间相机传感器的 CSI-2 链路归属，支撑「离开锁定」「接近唤醒」「自适应调暗」等存在感检测功能。7.2 时 CVS 已为 Arrow Lake / Lunar Lake / Panther Lake 启用，7.3 则扩展到 Nova Lake（仅需新增 PCI 设备 ID 与 ACPI ID）。媒体侧其他 7.3 改动还包括：Qualcomm Milos VPU 2.0 加入 Iris 驱动（SM7635 / 骁龙 7s Gen 3）、Dreamchip RPPX1 ISP 框架、Renesas VSP1（RZ/T2H、RZ/N2H）、V4L2 内核允许未知 HDR10 白点与亮度值，以及 Sony IMX678 / IMX471m、Himax HM1092 IR 传感器支持。
关注理由：CVS 驱动把「存在感检测」这类现代笔记本/台式机的智能感知能力带到 Linux 内核，且随 Nova Lake 延续支持，意味着新一代 Intel 平台的相机/感知功能在开源栈上可无缝延续。对做 Linux 笔记本相机、智能感知或 V4L2 媒体 pipeline 的开发者，这是媒体子系统在 7.3 的务实进展。
